# CRLM 项目：执行 M0–M1 提示词

## 使用方法

先审阅项目计划并退出界面的 Plan 模式，再粘贴下方正文。本提示词授权本轮执行 M0–M1，适用于当前工作目录就是项目根目录的情况。若实际模式仍限制写入，Agent 应准确说明限制，不能声称通过文字自行切换模式。

我现在授权你在本项目中执行 **M0–M1**。请依据已确认的计划和项目材料自主完成当前阶段内必要、低成本、可逆的工作，持续推进到有证据支持的完成状态或具体无法排除的阻塞；不要每完成一步就重新询问是否继续。当前授权不扩展到 M2–M8、外部验证、全队列模型训练、受控数据申请或向他人发送消息。

## 一、启动时核对范围

先确认实际模式允许执行，遵守当前有效的系统、开发者、用户及工作目录指令。读取根目录和相关子目录的 `AGENTS.md`，随后读取：

- `docs/source_brief/说明.md`：项目研究意图的最高材料依据。
- `docs/CRLM_Research_Plan.md`、`docs/IMPLEMENTATION_PLAN.md`。
- `configs/project.json`、`docs/COMPUTE_GUIDE.md`（若存在）。
- `references/reading_manifest.csv` 及完成当前数据身份/处理判断所需的原始记录。
- `starter/README.txt`、相关脚本和审计材料；已有阶段记录及 Git 工作区状态。

保留用户现有改动，不重置、清空或覆盖与本任务无关的文件。已有材料能回答的问题自行解决；冲突按原始来源核实并记录。计划或关键输入缺失时，先完成不依赖它的核查，列明最小阻塞，而不是编造文件或完成记录。

本项目目标是跨患者、跨来源复现的免疫状态与程序，分类用于发现和检验信息。当前 106 项检查是旧包的合成/逻辑验证；`artifacts/handoff/` 只证明交付骨架被检查过。不能把它们直接记为你已完成 M0，也不能声称真实 QC、编码或模型训练已经做好。

## 二、资源与权限的执行原则

用户本地硬件为 **i5-13400、64 GB RAM、400 GB 空闲 SSD、Intel Arc A750**。先探测真实 OS、可用 RAM/磁盘、Python/R 和依赖版本、驱动及可见的 CPU/CUDA/XPU 能力。CPU 是 M0–M1 默认路线；Intel GPU 后端或 R 尚未就绪时，记录其影响，继续不依赖它们的工作。不为探测 GPU 就盲装整套深度学习环境。

先复用可追溯的已有下载、隔离环境和审计文件；需要时在项目局部环境中补齐最小依赖。对下载和耗时操作先核验 URL/授权、文件大小、实际剩余空间、预计临时/解压开销；从小样本实测时间和峰值内存。不要先致密化大矩阵，也不要预设 A750 能运行 CUDA 实现。AutoDL/Colab 是否值得使用留待 profile 决定，不给未经测量的费用、显存或时长保证。

对本轮范围内的必要公开数据小样本下载、局部环境准备和可逆修复直接推进并记录。不要无理由对每个下载或安装逐项请示。需要超出当前范围、消耗显著外部费用、执行长时大训练、访问受控材料或不可逆外部操作时，先给出具体规模/成本依据和可评审选择；当前授权不包含绕过访问限制或代发邮件。不可取得的数据明确记为 unavailable/blocked，不补造内容。

## 三、M0：环境、材料与身份底座

### M0.1 环境与现有状态

按实际配置的目录与 schema 记录 OS、软件版本、依赖/硬件、可用资源、运行时间、命令、退出码及已存在材料。使用 `artifacts/m0/` 保存本次记录，保留历史交付证据。不要虚构配置键或在未经阅读时修改工具接口。

### M0.2 复核既有代码能力

阅读旧包三套自检的实现与输出位置后再运行。能指定输出目录的使用本次阶段目录；会写到脚本旁的脚本，在隔离副本或其他可追溯方式中运行，保留原包及历史结果，记录所用代码哈希。重跑结果与原 33+41+32=106 项口径对照，失败如实保留并修复当前范围内的问题。不要通过删测试、降低断言或复用旧 JSON 把未通过写成通过。

这些检查证明代码逻辑与接口，不证明真实生物学。新的验证聚焦身份对齐、矩阵轴、缺失/零、尺度、患者去重和输出可重读等真实风险，避免把无关测试数量当进度。

### M0.3 患者、样本、来源和角色

复核 `starter/audit_data/` 的 245 manifest 及原始临床/官方样本来源，使用既有校验入口产出本次验证结果和合法患者分折文件。至少分清 donor、sample、lesion、tissue、cohort、role、input_scale、患者映射核实状态、临床窗口与来源证据。

历史预期为 GSE245552 的 39 个样本、16 位公开 scRNA 患者、13 个完整 PT–LM 对，Pt18 有四组织；将实际结果与其核对，不强行凑数。Pt16_T1 的组织不能由名字推断；多病灶不能增加独立患者数。治疗与配对时序未核实项保留 unknown/timing-unverified。

保持主路线角色：245 开发；164 外部四组织复现；178、203608 次要方向复现；225 身份未解决时不进配对主检验。本阶段不把新外部表达效应引入候选选择，不消除既有暴露记录。

**M0 通过条件：** 本次环境/资源与依赖有记录；旧包检查实际运行且结果可核；manifest 无未处理的硬身份冲突；阶段角色、缺口和来源明确。能继续的部分继续执行；被阻塞部分单独标明，不将整阶段伪标完成。

## 四、M1：最小真实样本导入与 QC 能力核验

### M1.1 先固定样本集合，再读取表达

按计划选择 245 一对 PT–LM 和 Pt18 四组织。选择依据是 manifest、临床映射和可获取性，不是预期候选效应。如果 Pt18 已是所选肿瘤对，取样本并集、去重下载，只计同一个患者；是否增加另一对由既定计划与具体必要性决定。记录选择理由、样本 ID、组织、病灶和所用原文件。

仅获取本阶段所需公开文件。核验哈希、压缩格式、矩阵维度、稀疏索引、非负性/整数值、barcode/feature 唯一性与行列映射。dtype 或整数性本身不能证明未经处理的原始 UMI；来源与数值检查分别记录。

### M1.2 保存忠实且可追溯的稀疏对象

保留原文件与原始 feature/barcode，生成可重读的按样本稀疏 H5AD 或项目约定对象。明确矩阵方向、`cell_uid` 与样本/患者/病灶映射、基因 ID/符号、表达尺度、原始 counts 所在位置及全部处理步骤。文件命名和路径遵从实际工程配置，产物写入 `data/processed/` 与 `artifacts/m1/`。

245 肿瘤与邻近组织 feature 范围不同：保留各自测量范围与映射；联合分析采用明确的共同可测集合或显式 missingness 设计。不能把外连接产生的缺基因补成“测得表达 0”，也不能悄悄丢弃基因后声称全部程序均完整。已有文献种子只是候选来源，不在本阶段凭表现删改或冻结签名。

### M1.3 QC 能力与初级免疫谱系

先核验哪些 QC 指标确实可算。245 肿瘤公开矩阵已缺全部 MT 基因，`pct_mt` 应标不可由当前数据重算，而不是 0；UMI/检出基因数也受到作者 feature 过滤影响。报告此范围内能观测的分布、异常及限制，保留过滤前后数目与原因；不直接照搬完整 Cell Ranger 矩阵阈值。

使用可取得的作者注释、原始 marker 表和透明标记检查建立初级谱系对照；明确哪些是作者标签、自动建议、人工确认或未定。输出 T/NK、Mono/Mac/DC、B/Plasma 的最小覆盖检查，同时保留 Neutrophil、Mast、非免疫及未定类别；不要为了凑三袋强制归类。这里是小样本注释可行性检查，不是全队列可靠状态发现。

汇总每样本和患者×组织的输入细胞、当前保留细胞、各谱系数、feature/程序测量覆盖和失败原因。保持分母一致并披露富集状态 unknown，不能把捕获细胞比例当单位组织天然比例。单对或单患者四组织的输出只支持导入/QC 可行性，不支持统计复现、器官独立机制或分类性能。

### M1.4 验收

重新打开生成对象，验证维度、稀疏性、轴顺序、sample/cell 映射及原始计数保存位置；对若干预先固定的条目与源矩阵比对。检查同患者重复样本未多算、缺基因未伪填零、无法测量的 QC 项保持缺失。记录峰值 RAM、耗时、磁盘占用和失败重试。保留可重跑命令与源文件/产物哈希。

**M1 通过条件：** 所选真实样本可以由源文件重建；对象能重读且身份/轴一致；测量能力与限制明确；初级谱系覆盖可检查；所有输出都有来源、尺度和当前处理状态。仅写出导入脚本、运行合成 demo 或得到一个 `.h5ad` 文件都不充分。

## 五、本轮工作边界与最后交付

本轮不开展全队列 M2、不训练 scGPT/MIL、不做正式 DE 或新外部程序效应、不冻结生物候选，不把单对数据用于调参或报告 AUROC。为后续保留固定编码器、患者分折、折内学习、简单基线与公平对照的接口即可。

工作中给简短进度说明，重点报告发现、实际阻塞和下一步验证，不重复征求已授权步骤的许可。遇到阻塞先尝试同范围内合理的可逆替代；仍无法解决时，明确缺什么、已完成什么、下一步需要什么。

结束时更新项目实际存在的阶段状态/进度记录，并在聊天中自包含地交付：

1. M0 与 M1 各自的 `completed / partial / blocked / not_started` 状态及对应证据；按项目 schema 使用等价值，不改写历史。
2. 新增/修改文件、真实运行命令、检查结果、实际样本/患者/细胞数及资源实测。
3. 数据身份、尺度、QC、基因缺失和初级注释的关键发现与限制。
4. 未完成事项、失败原因、是否需要云资源的当前依据；没有 profile 支持就不下“必须上云”或“本地一定够”的结论。
5. 最小下一步 M2 建议与依赖，但不在本轮自动执行。不要把弱数值、模拟、历史报告或仅可运行代码包装成真实研究完成。
