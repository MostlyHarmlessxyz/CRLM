# CRLM 项目分阶段实施计划

## 0. 定位、当前状态与路径约定

本计划将上一轮研究方案转成可验收的实施顺序。项目目标以 [原始最终说明](source_brief/说明.md) 为准：发现能够跨患者、跨独立队列重复的免疫细胞状态与分子程序，区分组成变化、类型内状态及器官背景；分类用于筛选和检验信息。完整推理、文献和数据限制见 [研究报告](CRLM_Research_Plan.md) 第 1–18 章及附录。

本次交付的是工程骨架及研究快照。85 条主参考文献、既有文件审计与 106 项合成检查不表示真实队列分析已经完成；它们也不等于 85 篇均已取得或精读全文。`artifacts/handoff/` 只记录本次骨架检查。M0–M8 均须以目标环境中的实际产物判定状态，不因目录存在而标记完成。

候选、检验计划和完整分析配置仍是 **DRAFT**。只有实际确定基因集、身份/角色、评分、方向、覆盖、比较家族、代码版本并形成可追溯存档后，才可登记真实冻结。现有外部资料暴露已经发生，不能把后续冻结称为从未看过外部信息的预注册。

### 0.2 本地优先与执行边界

用户本机为 **i5-13400、64 GB RAM、约 400 GB 可用 SSD、Intel Arc A750**。M0–M1 从 CPU 和小型稀疏数据开始；患者统计及透明线性 MIL 可沿用 CPU 路线。A750 不代表 CUDA 可用，scGPT 及其依赖在目标环境中的 GPU/后端兼容与加速效果仍需实测。

每次大下载、解压或编码前，依据实际剩余空间和小批量 profile 估计原文件、临时文件、派生对象及缓存的同时占用。为系统与暂存留余量，避免把 400 GB 全部用作下载预算；避免复制相同大矩阵。首轮只获取最小 slice，不启动全部 FASTQ、全图谱或所有外部表达下载。云端是编码/计算阶段的备选，先明确瓶颈和输入范围，再依据 `COMPUTE_GUIDE.md` 与用户授权选择；不预填价格、GPU 耗时或兼容性结论。

用户要求 PLAN 时先只读盘点与生成计划；执行授权后按阶段推进。下述“暂停”是停止受影响的科学结论或高成本扩展，允许继续其他独立工作，不构成反复确认的通用流程。

## M0 — 环境、来源与身份底座

**输入：** 原始需求、完整研究报告、实际项目配置、`starter/README.txt`、原审计与 manifest、论文读取深度、既有外部暴露记录。

**实施：**

1. 盘点真实文件、脚本、依赖、磁盘与运行环境，区分本机能力、缺少材料和仅规划的功能；不把当前云工作区的硬件检测冒充用户本机检测。
2. 确认 V1 角色：245 开发；164 主外部/背景；178 次要；203608 冻结前可选次要；225 身份阻塞。逐项记录证据来源，不默默改角色。
3. 读取真实 245 manifest 的患者、sample、lesion 和组织映射；保存 39 样本、16 患者、13 完整肿瘤对的既有口径及需要现场复核的字段。尚未做细胞 QC，不能把 13 当各谱系最终 N。
4. 保留历史自检结果及 SHA，在隔离工作副本或脚本支持的独立输出路径复跑原三套自检。隔离副本只复制代码与必要的小合成材料，不复制大表达矩阵。
5. 对原入口的依赖和参数做实际检查；在隔离副本的 `starter` 目录运行 `python selfcheck.py`、`python mil_selfcheck.py`、`python registered_tests_selfcheck.py`。三套历史期望为 33、41、32 项；差异须解释，不能改计数掩盖失败。
6. 将既有外部暴露事实导入项目日志；对核心全文缺失、受控访问、未知治疗及 225 身份问题建立待办。优先低成本只读核验，不要求实现者在开始前读完全部文献。

**输出：** `artifacts/m0/input_inventory.csv`、`environment_report.md`、`data_role_decisions.md`、`manifest_review.md`、`baseline_checks/`、`external_access_log.csv`、`stage_report.md`。这些是待生成文件。

**通过：** 能指出每个输入来源和角色；可区分已证实与待查字段；当前样本集没有未处理的硬身份冲突；原三套合成检查在目标环境实际通过；首轮磁盘与计算范围明确。只定位环境阻塞而未成功运行检查时，M0 标记 partial/blocked，不标完成。实际表达尚未导入不单独阻止 M0 环境/来源验收，但 M1 仍未完成。

**暂停/替代：** 关键源文件缺失先定位已有附件和公开原始入口；依赖冲突用独立环境解决。患者身份/组织标签冲突暂停该样本配对，保留原因。大文件不可得时交付精确缺件清单及下载计划，继续小合成与元数据工作。

## M1 — GSE245552 最小真实稀疏导入与 QC 能力

**输入：** M0 核验的 manifest；一位核实患者的一对 PT–LM；Pt18 的 PT/LM/NC/NL；相应官方矩阵、基因、barcode 和来源记录。优先选最少、足以检验接口的样本，不预设全部矩阵已在项目中。

**实施：**

1. 依据 manifest 选择 sample；选中肿瘤对若包含 Pt18，与其四组织取 `sample_uid` 并集。Pt18 不增加第二个患者，重复病灶/技术文库也不增加患者。
2. 对最小文件集记录来源、大小和 SHA，核对 MTX 方向、维度、索引、非负整数值、gene/barcode 长度与唯一性。保存 source gene ID、标准化 ID 与映射冲突，不覆盖原件。
3. 实现或复用最小稀疏导入，保留原计数和输入尺度说明。避免整份 `toarray()`，用实际峰值内存决定下一批大小。
4. 明确 245 的不完整基因轴：PT/LM 29,569；邻近 29,922；共同提供基因与缺失集合单列。肿瘤 pct_mt 为不可计算，不能以空 MT 集合得到 0 并判高质量。
5. 只计算当前交付范围允许的可见 counts/n_genes 等指标；不声称完整 CellRanger QC，也不机械沿用完整基因轴阈值。注释先到可信大谱系，保留 unknown、Neutrophil/Mast 和疑似混合细胞。
6. 生成患者×组织×谱系覆盖表；对少量细胞核查表达/注释一致性。这是导入与覆盖验证，不做候选效果选择、不训练分类器、不展开新外部程序效应。

**输出：** `data/processed/m1/` 的稀疏对象与来源描述；`artifacts/m1/sample_selection.csv`、`matrix_audit.csv`、`gene_coverage.csv`、`qc_capabilities.csv`、`lineage_coverage.csv`、`resource_profile.json`、`stage_report.md`。

**通过：** 从原文件可重建对象，样本/患者/细胞一一可追溯；原表达与对象中抽查值一致；缺失基因与真实零值区分；Pt18 去重正确；细胞覆盖与不可计算 QC 指标明确；运行成本有实测记录。

**暂停/替代：** 标签或 barcode 无法对齐则停止该输入；内存超出预算缩小分块而非致密化；无法可信细分则留在父类/unknown。只见一个患者的效应不得形成群体差异结论。

## 首轮交付：M0–M1 的纵向最小流程

首轮执行目标是“需求/来源 → 身份 manifest → 一个小型真实稀疏对象 → QC 能力与覆盖报告”，再附原统计原型在合成数据上的运行证据。真实稀疏导入与合成统计流程应明确标记两条不同证据链；不把合成程序分数接到真实样本上制造结果。

| 顺序 | 具体动作 | 验收证据 |
|---|---|---|
| 1 | 阅读最终说明、报告有关数据与实施章节、实际配置和 starter 入口 | M0 目标、角色、缺件和资源记录 |
| 2 | 只读核 manifest 与历史审计，保留原证据；在隔离副本复跑 106 项原检查 | 三份实际结果及命令、环境、SHA |
| 3 | 选一对 PT–LM 与 Pt18 四组织，做 sample 并集 | 无重复患者/样本的 selection 表 |
| 4 | 取得最小文件集并稀疏导入 | checksum、形状、索引、值域、条形码与对象一致性 |
| 5 | 标记 QC 能力，形成初级谱系覆盖及 resource profile | pct_mt 不伪造，unknown 与排除原因可追溯 |
| 6 | 汇报已完成、未完成、阻塞和 M2 的具体输入需求 | M0/M1 阶段报告，不写真实模型性能 |

首轮验收不以新候选、AUROC、完整 39 库注释或大模型跑通为条件。若某真实文件尚不可得，交付来源/环境与准确阻塞，M1 保持未完成；不改用虚构矩阵充当真实流程成功。

## M2 — 全发现队列的覆盖、注释与处理分支

**输入：** M1 合法导入器、245 全部可获得样本及既有原始审计、开发阶段预定 QC/注释规则。

**实施：** 按分批资源预算扩展到 245；只在开发数据制定 QC、marker 组合和可信细胞层级。区分同捕获重复测序、独立捕获和不同病灶；先去重，再决定聚合。完成 T/NK、Mono/Mac/DC、B/Plasma 主任务覆盖，保留其他类型及 unknown。记录每个亚型的患者/组织资格、缺失机制、治疗/episode 不确定性。

为 counts 伪批量与连续程序评分保存不同但一致可追溯的输入。前者可采用同患者/组织的合法计数合并，后者采用病灶等权；不要把两个估计对象混写。跨组织需要明确共同提供的基因与排序背景，不能给被删基因填生物学 0。

**输出：** `data/processed/m2/`；`artifacts/m2/qc_and_exclusions.csv`、`cell_annotation_provenance.md`、`donor_tissue_lineage_coverage.csv`、`gene_universe_audit.md`、`pseudobulk_manifest.csv`、`stage_report.md`。

**通过：** 能解释每个有效患者数；主谱系映射有可复核证据；raw/processed 能力正确；各版本能从原件重建。对新增和既有审计差异给出原因，不因早期 13 对而固定分析 N。

**暂停/替代：** 某细类型覆盖不足时按事前标准合并到父类或转为丰度分析；不能降低阈值追显著。若某谱系无法支持训练，仅保留覆盖结果和失败原因。

## M3 — 患者级程序、组成与开发证据

**输入：** M2 对象与覆盖；已核验的文献程序种子、完整基因集来源；仅开发患者的发现数据。

**实施：**

- 将文献完整程序、DEG/通路交集、少数 marker 和技术读出分别标注；种子文件不自动成为冻结签名。
- 先实现固定程序及患者汇总；需要新发现时在 245 内限定 cNMF 等搜索范围、秩和稳定性评估。
- 程序分数先 sample/lesion，再患者/组织等权；形成 D_T。245 的单个完整四组织患者只给个体描述。
- counts 只在核实来源和共同可测范围内进入 donor-aware 伪批量；处理后表达走固定 rank/连续分数分支。
- 分开报告比例与类型内程序；对称分解需要两侧条件均值可测，否则报告共同支持与不可识别部分。
- 输出患者效应、离群患者影响、覆盖、技术/器官背景对照和基因重叠；开发 p 值不当外部复现。

**输出：** `artifacts/m3/program_definitions_draft/`、`sample_program_scores.csv`、`patient_effects/`、`composition_results/`、`candidate_evidence_draft.md`、`stage_report.md`。

**通过：** 少数候选有完整的来源、可测性、患者效应与稳定性证据；零个可靠候选也是有效阶段结论。已知效应必须按已知效应记录，不能因聚类重命名声称新机制。

**暂停/替代：** 单患者、技术变量、区域或组成主导时先改变恰当解释/范围，暂缓深模型；需要改变候选定义时只在开发阶段更新版本。

## M4 — 受控基线、冻结表示与有限 MIL

**输入：** M2/M3 合格开发患者；患者分割；事先固定的文献程序或合法折内新程序；本地资源 profile。

**实施：** 先程序/组成 Elastic Net、PCA 均值线性头，再 PCA/scGPT × mean/attention 的有限比较。HVG、PCA、标准化、筛选、程序发现和超参数拟合均在合法训练范围；若用全开发集发现新程序，不能再把同集普通 CV 当无泄漏评估。保存外层 OOF，不用其结果不断调参。

scGPT 编码先审计 checkpoint、词表、实际代码和输入能力，再做小批量时间/内存/兼容性 profile；记录逐细胞随机流与缓存身份，验证同一细胞/样本在不同批次组合中的稳定性。64 GB 主机与 A750 的实际表现用测量决定，失败可保留 CPU/PCA 路线，或形成明确范围的云端编码方案；不承诺尚未验证的 XPU/FlashAttention 兼容。

MIL 按患者→组织→病灶→技术样本等权 BCE，配对患者只贡献一次 m=0 的 softplus 排序。正常组织不入肿瘤 BCE，背景不进入会奖励负 D_N 的主损失。HA/CTA 和 MixMIL 在简单流程稳定后接入；各模型使用同谱系细胞和相同分割，另记真实适配、总优化参数与预算。

**输出：** `embeddings/`、`models/` 及绑定的来源/训练患者/变换记录；`artifacts/m4/split_manifest/`、`benchmark_runs.csv`、`oof_predictions.csv`、`paired_model_comparisons/`、`resource_profiles/`、`stage_report.md`。

**通过：** 所有任务无患者交叉；共同可用样本比较公平；指标先患者组织级聚合；合格率与失败运行完整。简单模型胜出可以通过本阶段。attention 不直接命名生物机制，预测也不是未来转移风险。

**暂停/替代：** 身份泄漏、外部参与特征拟合或输入尺度错误先修复；深模型不稳定时保留强简单基线。依赖/硬件失败登记为未运行，不填 AUROC=0。

## M5 — 冻结候选、测量规则与验证版本

**输入：** M3/M4 开发证据、外部测量能力和已发生暴露记录；尚未用于更改候选的新外部程序效应不应提前计算。

**实施：** 冻结总共 2–3 个主要 `lineage::program` 候选及程序版本、基因集/方向、评分/排序背景、覆盖和缺失规则、临床窗口、主检验、ties 规则及 family。保留原始计数/连续效应的尺度差别。冻结模型则同时存训练患者、checkpoint/变换、阈值、代码和所有输入 SHA。

主族是 GSE164522 的候选 D_T、双侧精确 sign test＋Holm；方向规则沿用登记工具的均值和非零患者多数方向同时符合预期。178 次要，203608 在本阶段前决定是否整组预登记为独立次要来源；次要显著性不是主复现门槛。四组织 I 另族，且并列 Q 子集的 D_T_Q/D_N_Q；每族 0.05 不宣称全研究共同 0.05。

将计划 CSV 与源码、基因文件、配置一起存档，再记录实际冻结日期/版本。不可测的计划测试依然保留，raw_p 为 NA，Holm 专用向量 p=1。DRAFT 只有在这些事项真实落实后才改变状态；既有 164 暴露仍需披露，冻结不抹除历史。

**输出：** `artifacts/m5/frozen_candidate_registry.csv`、`registered_tests.csv`、`gene_sets/`、`freeze_record.md`、`external_access_log.csv`、相关 SHA 清单与 `stage_report.md`。

**通过：** 每项主张与输入可唯一匹配；计划缺失、反向、ties、亚型缺失和基因不可测都有预定处理；方法与检验没有待结果出现才选择的分支。

**暂停/替代：** 候选/方向/覆盖或身份尚不明确就保持 DRAFT；继续开发或缺件核查，不先生成外部效果再补填冻结。用户决定 V2 合并训练时另建全套角色与确认策略。

## M6 — 外部复现、四组织与失败解释

**输入：** M5 的实际冻结包；164 processed-only 合格输入；178、被预登记的 203608；其他来源仅按已登记角色。

**实施：** 先按冻结规则生成可测/不可测清单，再应用固定注释和评分，不在外部重做 HVG、候选挑选或效果导向的归一化。逐队列形成患者 D_T，164 另在同一 Q 中计算 D_T_Q、D_N_Q、I。已有暴露事实保留；每次新访问与技术更正追加日志。

实际 `effects_summary.csv` 进入 `starter/adjust_registered_tests.py` 的冻结计划匹配。重复键拒绝、缺失成员保留、计划外结果单列。报告效应、方向、区间和 N，再报告检验；178 的 6 人与 203608 的 4 人主要提供方向/精度信息，不为了显著事后合并。

**输出：** `artifacts/m6/<cohort>/coverage/`、`patient_effects/`、`registered_tests/`、`model_predictions/`；`cross_cohort_evidence_cards.md`、`external_access_log.csv`、`stage_report.md`。

**暂停/替代：** 原始映射/输入软件错误可修正并保留前后版本；若因外部生物效应不合意而改程序、类型或方向，新版本转探索性并需新确认材料。背景 N 不足保留肿瘤差复现与明确局限。

## M7 — 限定空间支持与实验准备
